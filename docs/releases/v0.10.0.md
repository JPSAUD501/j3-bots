# J3 Bots 0.10.0

**Draft.** The notes for the 0.10.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

The first run is rebuilt for someone who has never heard of a harness. It says what J3 Bots is before it installs anything, downloads the AIs as the server starts, asks which account you have, Claude or ChatGPT, and a new bot says hello in a few short messages. Settings shows only what your bots added. Behind it, a sweep of the issue tracker: the server on Windows, Stops that reach everything, signed bot tool calls, and moving your bots to another server. It still pins T3 Code 0.1.11.

## Updating

This release speaks **protocol 11**, as 0.9.0 does, so an app and a server on 0.9.0 and 0.10.0 keep talking in either order. Update the server first anyway: the new first run and the new hello need it.

- **The server:** from an app, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases into a snapshot first, then runs this release's migrations:
  - **0044** marks the device the desktop app signs in on its own computer, so it keeps one at a time.
  - **0045** records when the server asked the engine to open a session, so a session lost to a crash is archived on the engine too.
  - **0046** ties a refused permission mode to the engine start that refused it.
  - **0047** stops a push about a bot's browser asking for help from showing the bot's note.
  - **0048** records the work a bot's turn caused in another room, so that room's Stop reaches it.
  - **0049** records when the engine took a steer, and each delegated task's report it carried to another conversation.
  - **0050** records which engine the sessions belong to.
  - **0051** records when each bot first spoke, so a bot made for a room says hello once.
  - **0052** adds the card a bot shows when it asks your yes to add a connector.
- **The desktop app and the Android app** update themselves as they open, or from the prompt every paired app shows. The deb and the Mac build link to this release.
- **The web client** comes with the server.

### Rolling back

`j3-bots update --rollback` to 0.9.0 puts back the databases from the snapshot, so the messages, rooms and changes made since the update are lost with the rest of the database. The apps keep talking to it, since 0.9.0 speaks protocol 11 too. Don't start 0.9.0 by hand on the updated data: it refuses a database with these migrations, and says to roll back.

## What's new

### The first run

- **It says what J3 Bots is first** ([#332](https://github.com/JPSAUD501/j3-bots/pull/332)). Three short steps, carried by the cast on the stage: a small team of bots of your own, what they do for you day to day, and that they think with an AI you already have, which J3 Bots installs for you. One quiet line, "Preparing your computer…", shows the downloads going on behind every step and never stops one. The spotlight is now light: a soft cone with haze in it, a pool on the floor, the lit bot with a rim and a shadow, and the others in the spill. A new bot arrives in one clean moment, the light swelling and settling, in place of the rings that glitched.
- **The AIs download as the server starts, and fail with the true reason** ([#327](https://github.com/JPSAUD501/j3-bots/pull/327)). Claude Code, Codex and the engine download in parallel as soon as the server starts, local or installed, without waiting for a step or a choice. On Windows, installing a harness failed with "check its free disk space" on computers with plenty of it: the new copy was run from where it was unpacked, and Windows then refused to move a program that was still open. It is moved first and run after. A failure now says what happened, a file another program holds, a folder the server may not write, a place outside its home, damaged files, and only a full disk speaks of disk space. The code and the path go to the server's log.
- **Connecting an AI is picking the account you have** ([#331](https://github.com/JPSAUD501/j3-bots/pull/331)). The step asks one question, Claude (by Anthropic) or ChatGPT (by OpenAI), with a big button each. The sign-in is drawn in three steps: a page opens in the browser, you sign in, you come back, and the app notices on its own. A download in progress shows as calm progress, and you can sign in or create your bot meanwhile: it says hello once its AI is ready. The engine's own words are kept under Details. Settings → Providers and a bot that can't run show the same path.
- **A new bot says hello, it doesn't set up** ([#328](https://github.com/JPSAUD501/j3-bots/pull/328)). Its first contact is two or three short messages, paced like a person typing, with "Typing" shown between them: who it is, what it can do for you, and one easy question. Where your work is kept, folders, accounts and connectors are asked only when a task needs them. A Stop drops the messages still to come. A bot made for a room does the same the first time it speaks.

### Settings

- **Settings lists what your bots added** ([#329](https://github.com/JPSAUD501/j3-bots/pull/329)). J3 Bots' own skills are no longer listed, though the bots still have them. The forms to add a skill or an MCP server by hand and the connector library are gone: you ask a bot, as since 0.9.0. Settings still turns each one off, removes it, gives it a secret and signs it in. The server keeps its add calls, so an app on 0.9.0 still works.
- **A bot asks your yes for a connector that needs it** ([#333](https://github.com/JPSAUD501/j3-bots/pull/333)). One at an address in your own network, or one that signs in with an app you register, such as Google or Slack, shows a card in the conversation. It's added only if you say yes, and the ask expires after a day or a restart.
- **Move your bots to another server** ([#317](https://github.com/JPSAUD501/j3-bots/pull/317), [#325](https://github.com/JPSAUD501/j3-bots/pull/325)). `j3-bots export` writes the bots, their memory, skills, files, attachments and secrets to one file under a passphrase, and `j3-bots import` brings them in on another server. On the desktop, Settings → Where your bots live → Move to another server does the export. Paired devices, the providers' sign-ins and the sessions stay behind: each device pairs again, and each bot goes on in a new session with its conversation and memory.

### From the issue sweep

- **The server on Windows** ([#309](https://github.com/JPSAUD501/j3-bots/pull/309), [#304](https://github.com/JPSAUD501/j3-bots/pull/304)): the home and the providers' folders kept private, a server left behind ended only if it is really the one the app started, and local mode's restarts and sign-ins made whole.
- **Stop reaches everything a stopped turn caused** ([#310](https://github.com/JPSAUD501/j3-bots/pull/310)), in other rooms too, and a steer counts once the engine took it ([#315](https://github.com/JPSAUD501/j3-bots/pull/315)).
- **Signed bot tool calls** ([#316](https://github.com/JPSAUD501/j3-bots/pull/316)): the server and the bridge to each bot's tools sign every request and answer with a key that lives only in the server's memory.
- **Connectors** ([#307](https://github.com/JPSAUD501/j3-bots/pull/307)): a connector keeps where it sends a secret, a secret of 4 to 7 characters is scrubbed where it stands as a word of its own, and idle sessions make room.
- **A provider check that timed out is tried again** on its own ([#300](https://github.com/JPSAUD501/j3-bots/pull/300)).
- **Updates and the desktop** ([#299](https://github.com/JPSAUD501/j3-bots/pull/299), [#306](https://github.com/JPSAUD501/j3-bots/pull/306)): a failed check tries again, a restart waiting for saves can be called off, and update, rollback and snapshot edge cases are closed.
- **The bots know this release**: a `j3-app` skill carries its notes ([#302](https://github.com/JPSAUD501/j3-bots/pull/302)).
- And more fixes across the clients, routines, the engine's edges and the release builds ([#297](https://github.com/JPSAUD501/j3-bots/pull/297), [#301](https://github.com/JPSAUD501/j3-bots/pull/301), [#305](https://github.com/JPSAUD501/j3-bots/pull/305), [#308](https://github.com/JPSAUD501/j3-bots/pull/308), [#311](https://github.com/JPSAUD501/j3-bots/pull/311), [#312](https://github.com/JPSAUD501/j3-bots/pull/312), [#314](https://github.com/JPSAUD501/j3-bots/pull/314), [#318](https://github.com/JPSAUD501/j3-bots/pull/318)).

## Known limits

**Not tried for real yet:**

- **The Android app** didn't run on a phone: the story steps, the light, the arrival, the connect step and the paced hello were checked by their tests only.
- **A harness install on a real Windows computer.** The fix is proven on CI's Windows machine against a local copy of a release, not against a download on someone's computer.
- **What a model does with the new hello**: its eval cases are written and were not run.
- **Moving a home** between two real servers, end to end.

**Limits of this version:**

- **A bot made while its AI downloads waits for it.** If the download fails, the bot waits until "Try again" brings it, or until you sign in to the other AI.
- **A connector ask lives in the server's memory**: a restart drops it, and the bot asks again.
- Asking twice for the same connector shows two cards, and saying yes to both adds it twice ([#334](https://github.com/JPSAUD501/j3-bots/issues/334)).

Everything listed under "Known limits" in the [0.9.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.9.0) notes still applies, except the scrubbing of short secrets, which #307 does for values of 4 characters or more.
