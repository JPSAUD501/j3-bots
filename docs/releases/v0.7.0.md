# J3 Bots 0.7.0

**Draft.** The notes for the 0.7.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

A bot brings work to a room it is in from its own conversation, and the apps update themselves as they open. It still pins T3 Code 0.1.11.

## Updating

This release speaks **protocol 10**, as 0.6.0 does, so a 0.6 app and a 0.7 server work together, and the other way round: update them in any order.

- **The server:** from any device, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases into a snapshot first, then runs this release's one migration, 0033: it adds a table that records which turns relayed your request to a room (below). Nothing already stored changes.
- **The desktop app:** the AppImage and the Windows install update themselves, once the download matches the release's signature. The deb and the Mac build link to this release.
- **The web client** comes with the server.
- **The Android app** updates itself.

The update to 0.7.0 itself goes as before, with the tap or the restart you already know: updating by itself as it opens starts with 0.7.0, for the releases after it.

### Rolling back

`j3-bots update --rollback` to the 0.6 release you updated from puts back the databases from the snapshot, so the messages and rooms made since the update are lost with the rest of the database. Your apps stay on 0.7.0 and work with a 0.6 server, which speaks the same protocol. Don't start 0.6.0 by hand on the updated data: it refuses a database that has migration 0033, and says to roll back.

## What's new

- **A bot posts in its rooms from your conversation with it** ([#270](https://github.com/JPSAUD501/j3-bots/pull/270)). Ask a bot, in your own conversation with it, to take something to a room it is in, start work there or tell the room something, and it posts there itself and tells you it did, instead of asking you to go and write in the room. The post wakes the members it names, or every other member. It counts as your word: it starts the room's count of bot messages again, once per turn, so a room that went quiet starts again from your private conversation. A message you send while the bot is busy with other work counts only once it reaches the bot's next turn: a post to a quiet room from the busy turn lands but wakes nobody, and the bot tells you so.
- **The desktop app updates itself as it opens** ([#268](https://github.com/JPSAUD501/j3-bots/pull/268)). **Update automatically**, in Settings → About and updates and on by default, makes the launch wait up to five seconds for its check. A newer version found in that time is downloaded, checked against the release's signature and installed, and the app opens on it, with only "Updating to version …" and its progress on screen meanwhile. A slow or failed check opens the app as usual. A download that goes 30 seconds without progress, or takes more than five minutes, opens the app as usual and goes on in the background. A version found while the app runs installs when you quit it, or at the next launch; **Restart to update** stays for sooner. In local mode the bots on this computer start once the launch's update is over. Turned off, the app behaves as in 0.6.0. The deb and the Mac build still only say a version is out, and don't show the setting.
- **The Android app updates itself as it opens** ([#267](https://github.com/JPSAUD501/j3-bots/pull/267)). The same setting, in the app's Settings → About and updates, on by default: when the app opens, or comes back after an hour or more, a newer release whose signature checks out is downloaded and handed to Android's installer with no tap. On Android 12 and later the app asks Android to install it without a confirmation, which Android grants to an app updating itself; elsewhere, or where Android still asks, its one confirmation shows when you are back in the app. The app asks for "Install unknown apps" once, before it downloads anything. A failed or refused install says so in the update notice and is tried again at a later opening.

## Known limits

**Not tried for real yet:**

- **The Android update** was checked by its tests and type checks only. No CI job builds Android, so the release build is the first to compile its native change, and nothing ran on a phone: whether Android skips the confirmation for an APK first installed from the browser is what its documentation says, not yet seen.
- **The desktop app's launch update and install on quit** are covered by the update model's tests and CI's package builds, not by running a packaged app.
- **A bot posting from your conversation** was checked with real models on an earlier wording of the prompt (Claude Haiku and Luna, five runs each): none told you to go and write in the room. The final wording was not run against real models.

**Limits of this version:**

- **A launch can take longer** with Update automatically on: up to five seconds for the check on a slow network, and as long as the download when it finds a version, during which the app can't be used.
- **The server doesn't update itself**: you update it from any app in one tap, as before.
- **The nightly build** is failing ([#269](https://github.com/JPSAUD501/j3-bots/issues/269)), so the nightly channel has no build yet.

Everything listed under "Known limits" in the [0.6.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.6.0) notes still applies.
