# J3 Bots 0.9.0

**Draft.** The notes for the 0.9.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

Bots get the whole of MCP, apps drawn in the conversation, and skills, and they set up their own servers and skills. The vault becomes Secrets, with no password to type after a restart. Updates open in front of you, the server first and then the app, and the first run is a stage. It still pins T3 Code 0.1.11.

## Updating

This release speaks **protocol 11**, a new one: 0.8.0 spoke 10. An app and a server on different protocols don't talk to each other, so update the server first, then the apps.

- **The server:** from an app still on 0.8.0, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases into a snapshot first, then runs this release's migrations:
  - **0037** adds the card a bot shows when it asks you for a secret.
  - **0040** records who added or last changed each MCP server and skill, the operator or which bot.
  - **0041** gives every bot and room its visibility. Everything you had counts as your choice, and stays shown.
  - **0042** keeps a connector's tools, resources and prompts as its server lists them, with no review of changed tools.
  - **0043** keeps the apps a connector's tools draw, beside the call that opened them.
- **The desktop app and the Android app** update themselves as they open. Until they do, an app on 0.8.0 says the server is newer and offers the update that brings it forward. The deb and the Mac build link to this release.
- **The web client** comes with the server.
- **From 0.9.0 on**, a new release opens a prompt in front of every paired app. Its "Update now" updates the server, waits until it runs the new version, then updates the app it was pressed in.

**If you used the vault with a master password,** Settings → Secrets asks for it one last time. From then on the server keeps the key itself and never asks again. Until you type it, connectors that need a secret can't reach their services and no login can be filled. Each login gets a name from its old label, such as `github-work`, which you can change. A vault with nothing in it is replaced without asking.

### Rolling back

`j3-bots update --rollback` to 0.8.0 puts back the databases from the snapshot, so the messages, rooms, skills and connector changes made since the update are lost with the rest of the database. Your apps stop talking to it until they go back to 0.8.0 too, since 0.8.0 speaks protocol 10. Neither the update nor the rollback copies the secrets: they stay as 0.9.0 left them. If you typed the old master password in 0.9.0, 0.8.0 can't open them, so its connectors and logins stay unavailable until you update again. Don't start 0.8.0 by hand on the updated data: it refuses a database with these migrations, and says to roll back.

## What's new

- **Bots speak the whole of MCP, at its current version** ([#282](https://github.com/JPSAUD501/j3-bots/pull/282)). J3 Bots speaks MCP 2026-07-28 and falls back to older servers. Bots read a connector's resources and prompts, a server can ask you a question as a card in the conversation, and long calls report progress. You use a connector's prompts from a `/` menu in the message field. A connector's tools are the ones its server lists now, with no "accept new tools" step: the bot's permission mode is what guards them. A new connector goes to every bot unless you name some.
- **A connector's app opens inside the conversation** ([#280](https://github.com/JPSAUD501/j3-bots/pull/280)). A tool that comes with an interface (MCP Apps) shows it under the bot's work. It runs in an isolated frame that reaches only the network its server declares, and only its own connector, under the bot's grant. A message it proposes goes only when you press Send, and a link opens only when you press Open. Outside full access, each of its tools asks you before its first call.
- **Bots add their own MCP servers and skills** ([#278](https://github.com/JPSAUD501/j3-bots/pull/278)). A bot searches the gallery and the MCP Registry, adds, changes and removes servers, and saves or installs skills (Agent Skills, as in Claude Code). The primary bot manages everything; other bots only their own. J3 Bots asks nothing extra: the bot's permission mode is the gate. Every change shows who made it.
- **The vault becomes Secrets, with no password** ([#279](https://github.com/JPSAUD501/j3-bots/pull/279), [#291](https://github.com/JPSAUD501/j3-bots/pull/291)). Nothing to unlock after a restart or an update. You type a login or a value, or a bot asks for one with a card. A bot only gets a reference, `secret:<name>`, and the server puts the value where it is used: in a login it types for the bot, or in a connector's header, argument or variable as `${secret:<name>}`. Only the bots a secret allows can use it, or a connector that needs it.
- **Updates open in front, the server first** ([#284](https://github.com/JPSAUD501/j3-bots/pull/284)). When a release is ready, every paired app shows the version, what's new, "Update now" and "Later". "Update now" updates the server, waits until it runs the new version, then updates the app. It never stops a bot's work without asking, and a failure says why and where it stopped.
- **The first run is a stage, and the bots feel alive** ([#288](https://github.com/JPSAUD501/j3-bots/pull/288)). The bots come down into spotlights, and the one you make reacts to its name as you type it and to each shape and color you pick. A new bot or room drops into its place in the list. A bot's eye follows the pointer only from close by, a press holds it down and a tap gets an answer, and it breathes, blinks and looks around on its own.
- **Settings in pages, each setting in one place** ([#283](https://github.com/JPSAUD501/j3-bots/pull/283)). One list: You, Notifications, Appearance, Providers, Usage, MCP and skills, Secrets (with the bots' browser), Devices, Where your bots live, and About and updates.
- **Bots and rooms can be hidden** ([#286](https://github.com/JPSAUD501/j3-bots/pull/286)). A hidden bot or room leaves the list and keeps working; it's under "Hidden conversations" at the list's end. You set it when you create or edit one. A bot may hide the helpers it makes for itself, but what you set is never changed by a bot.
- **A mention shows the bot's face and color** ([#285](https://github.com/JPSAUD501/j3-bots/pull/285)), in the message field and in the conversation.

## Known limits

**Not tried for real yet:**

- **MCP against real servers.** The new protocol, the apps, the questions, tasks and secret references ran against test servers only, not against a real MCP 2026-07-28 server. The apps' isolation was not watched in a running browser or in the desktop app.
- **The Android app** didn't run on a phone: the stage, the entrances, the gaze that follows a finger, the mention chips in the message field and the update prompt were checked by their tests only. The mention field is compiled for the first time by this release's build.
- **What a model does with the new tools**: hiding only its helpers, adding servers and skills. No real-model run checked it.
- **An update from the prompt** against a real server, end to end.

**Limits of this version:**

- **The secrets' key lives beside them**, in the server's data directory, readable by the server's user and so by a bot's shell. Keep the server to a dedicated user on a computer that matters ([Operating: secrets](https://github.com/JPSAUD501/j3-bots/blob/v0.9.0/docs/operations/operating.md#secrets)).
- **A value shorter than 8 characters** isn't scrubbed from a server's answers ([#292](https://github.com/JPSAUD501/j3-bots/issues/292)).
- **On the web, the first run is always dark**, whatever the app's appearance.
- **An app's tool asks before its first call** outside full access, because the harness never sees those calls.

Everything listed under "Known limits" in the [0.8.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.8.0) notes still applies.
