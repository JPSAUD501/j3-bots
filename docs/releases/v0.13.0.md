# J3 Bots 0.13.0

**Draft.** The notes for the 0.13.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

Signing in to an AI is one row, and the browser opens by itself. You and your bots can react to messages. A bot arrives in your list as one moment, and its work says what it does in plain words, with no clock. A bot can wake on a connector's events, load the skills a connector offers, and connect to services that sign in as a service. On Android, you can share anything to a bot from another app, and keep one on your home screen. It still pins T3 Code 0.1.13.

## Updating

This release speaks **protocol 11**, as 0.9.0, 0.10.0, 0.11.0 and 0.12.0 do, so an app and a server on any of them keep talking in either order. Update the server first anyway: reactions, event routines, a connector's skills and the card for a service's values need it. Then update the apps. An app older than 0.13.0 shows no reactions, and doesn't list event routines: it shows their changes, and the run card of one in steps, as needing a newer version. It lists no skills on a connector's page, and shows the card for a service's values as one box whose answer is refused, so answer it on an updated app. A 0.12.0 desktop app also opens the sign-in page by itself, in its old layout.

**If you used the vault with a master password and never typed it in Settings → Secrets, open it with 0.12.0 first.** A server whose vault from before 0.9.0 still holds logins and was never opened refuses to start with 0.13.0. It changes nothing in the vault, exits with status 78, and says: "The secrets are in a vault from before J3 Bots 0.9.0 that was never opened. Open it with J3 Bots 0.12 first: start 0.12, type the vault's password where it asks for it, then update again." An update from 0.12.0 to such a server never becomes ready, so it is rolled back to 0.12.0, where the vault opens. A vault with nothing in it is still replaced without asking.

- **The server:** from an app, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases, the engine's too, into a snapshot first, then runs this release's migrations:
  - **0061** keeps reactions, one for each person or bot on a message, and one waiting its few seconds before it reaches its bot.
  - **0062** keeps where each event routine's listening left off, the events already taken and those waiting for the next run, and lets a conversation hold its changes and runs.
- **The desktop app and the Android app** update themselves as they open, or from the prompt every paired app shows. The deb and the Mac build link to this release.
- **The web client** comes with the server.

### Rolling back

`j3-bots update --rollback` to 0.12.0 puts back the databases from the snapshot, the engine's included, so the messages, reactions, routines and changes made since the update are lost. The apps keep talking to it, since 0.12.0 speaks protocol 11 too. Both releases pin T3 Code 0.1.13, so the engine's data is not moved forward. 0.12.0 refuses a database with these migrations: started by hand on the updated data, the server exits with status 78 and says to run `j3-bots update --rollback`.

## What's new

### Signing in to an AI, directly

- **Each AI account is one row** ([#361](https://github.com/JPSAUD501/j3-bots/pull/361)): its name, one line that says where it stands, and the one thing to do beside it. Claude and ChatGPT both show, and you sign in to the one you have: in the first run, in Settings → Providers, or in a conversation whose bot waits for its AI.
- **Tap Sign in with Claude and the browser opens by itself.** The row reads "Your browser opened. Sign in to Claude there.", then "Connected". A quiet "Browser didn't open? Open the page" stays under it while the sign-in waits.
- **From the web in a browser or from Android, the row shows How to connect**, which says where to sign in: only a browser on the server's computer can finish it.

### Reactions

- **React to any message with an emoji** ([#364](https://github.com/JPSAUD501/j3-bots/pull/364)): 👍 👎 ❤️ 😂 🎉 😮, or More for every emoji, from the React button on the web or a long press on Android.
- **One each, as in chat apps.** A new emoji replaces yours, and tapping yours takes it off. Who reacted is a hover or a long press away.
- **Your reaction on a bot's message reaches that bot**, a few seconds after your last change, so a 👍 on its offer can mean "go ahead". If it decides to say nothing, nothing shows. Other reactions wake no one. Bots react rarely, never to their own messages, and notify no one.

### A bot's arrival and a turn's work, in plain words

- **A new bot arrives as one moment** ([#365](https://github.com/JPSAUD501/j3-bots/pull/365)): a light in its color comes up in its row, its face falls into it, its name and line come in as it lands, and the light dims. Android gets the light too.
- **No working time anywhere.** No clock while a bot works, no durations on steps: a finished turn reads "Worked · 6 steps".
- **The working line says what the bot is doing**: "Running a command", "Editing a file", "Searching the web". The raw command shows only under that step, once you open its work.
- **Work that goes on after the reply is part of the turn**: its steps land in the same fold, with no "Still working in the background".

### Bots wake on a connector's events

- **Ask "tell me when Ana sends an invoice"** ([#368](https://github.com/JPSAUD501/j3-bots/pull/368)), and the bot looks at what the connector offers and sets a routine that runs when it happens. The routine reads "When Mail says a new email from Ana arrives", with the connector's icon.
- **The server listens, not the bot**, across restarts. Events that come during a run start the next one together.
- **An event routine can have steps**, as any routine: its track starts at the event, and each step gets what arrived.
- **When it stops, you hear why**: "Stopped: Mail no longer allows it" on the routine and a line in the conversation. The bot tells you and offers to set it again.

### Skills from connectors

- **A connector that serves skills gives them to every bot it is granted to** ([#366](https://github.com/JPSAUD501/j3-bots/pull/366)), with nothing to set. The connector's page lists them under "Skills it offers bots".
- **The work line names them**: "Using the skill reply-style from Mail".
- **A skill is checked before it is used.** One whose files don't match what the service listed is refused, in plain words.

### Connectors that sign in as a service

- **Some services sign in no person**: they take a client you register with them ([#367](https://github.com/JPSAUD501/j3-bots/pull/367)). The bot asks for its values on one card, the client ID shown and the client secret hidden, with a link to the service's page that issues them. The bot never sees them.
- **Refused values are asked for again**, on one card, and the service is asked nothing more until they change.
- **"Finish this step on the service's page"** becomes a card with that page. The call waits for you and then runs again once; a step you decline or leave is told to the bot.

### Share to a bot from Android, and a home-screen widget

- **Share a photo, a link, a PDF or some text from any app to a bot** ([#370](https://github.com/JPSAUD501/j3-bots/pull/370)). A sheet opens over that app with your bots' faces. Add a line, tap **Send to Wren**, and it goes as one message, without opening J3 Bots. Your bots are in Android's own share row too.
- **A widget keeps a bot or a routine in sight**: a bot's face and whether it is working, waits for you or is quiet; or a routine's name, "Ran 2 hours ago" and the start of its last result. A tap opens it.

### Less old code

- **What only releases nobody runs needed is gone** ([#363](https://github.com/JPSAUD501/j3-bots/pull/363)), from the code and the docs. The apps do what they did.
- **The old vault's password form is gone**: see Updating if yours was never opened. Android stops listing a notification channel nothing uses since 0.5.0.

### Fixed

- **A server stopped right after it started could keep running** ([#375](https://github.com/JPSAUD501/j3-bots/pull/375)), which made an update or a restart wait until it was killed. A stop now ends at once, and one that runs long says in the server's log what still holds it.

## Known limits

**Not tried for real yet:**

- **The Android app** didn't run on a phone: everything new in it was checked by its tests and types only. TalkBack was not tried.
- **The share sheet and the widget** were built for Android by the release, never run on a phone or emulator.
- **The desktop app** was not run: whether the browser opens on the tap there is assumed from how Electron works, not seen.
- **Real services**: no real authorization server for a service sign-in, no real MCP events server (the extension is still Beta), and no real service that serves skills. Each was tried against a fake one.
- **Against real AIs**: nothing ran, and the new tool wording had no real-model eval. Whether Claude Code or Codex also open a browser on Windows or macOS, leaving a second tab, is not known.
- **An update over a vault never opened** was not run; its rollback rests on the update's rule that a release that never becomes ready is rolled back. The React button was not tried on a touch screen.

**Limits of this version:**

- **One reaction each per message.** A bot can replace its reaction but not take it off. An archived room still offers reacting and refuses it. An app open across the server's update reacts only after a reload. On Android, selecting a message's text takes a second long press.
- **A fold left open as its turn ends** counts later steps in its title but lists them only once it is opened again.
- **An event a service stops offering** is noticed only when the service ends the listening or it starts over. A run takes at most 20 events; the rest wait for the next.
- **A skill a bot loaded is forgotten on a restart**, and the bot loads it again.
- **Service values** are only for a connector added by its address, not one from the list.
- **A notification doesn't update the widget**: it catches up when the app next connects. A routine's widget shows its last run in words when the result is older than the conversation's first page, and names the routine, not the bot, when the bot is gone.
- **A share with more files than one message takes** sends what fits and says how many stay behind.
- **The AI sign-in shows no account email**, since the engine doesn't report it.

Everything listed under "Known limits" in the [0.12.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.12.0) notes still applies.
