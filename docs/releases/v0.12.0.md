# J3 Bots 0.12.0

**Draft.** The notes for the 0.12.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

This release lets a routine pass from bot to bot, and wait for your yes where it matters. Documents open in the app's own viewer. On the desktop, quick access brings the window you were in. Each bot has an effort beside its model, one card asks for every value a sign-in needs, and a bot that asks before acting though you chose otherwise says why. The app has a new icon: "j3", with a bot's light on. It now pins T3 Code 0.1.13.

## Updating

This release speaks **protocol 11**, as 0.9.0, 0.10.0 and 0.11.0 do, so an app and a server on any of them keep talking in either order. Update the server first anyway: routines in steps, effort, the card with several values, the new notice and the window from quick access need it. Then update the apps. An app older than 0.12.0 shows a routine in steps by its first step only, and a run's card and the new notice as needing a newer version. It also says a secret is used "without seeing it" when the bot gets it as a file, which the bot can read: 0.12.0 says where each value goes.

- **The server:** from an app, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases, the engine's too, into a snapshot first, then runs this release's migrations:
  - **0057** records the newest engine release that ran on your bots' data, so an older one is never started on it.
  - **0058** keeps each bot's effort, empty for Default.
  - **0059** keeps which engine notices a bot has shown, so each shows once for each model.
  - **0060** keeps a routine's steps and each run's steps. Every routine you have becomes a one-step routine and works as before.
- **The desktop app and the Android app** update themselves as they open, or from the prompt every paired app shows. The deb and the Mac build link to this release.
- **The web client** comes with the server.

### Rolling back

`j3-bots update --rollback` to 0.11.0 puts back the databases from the snapshot, the engine's included, so the messages, rooms and changes made since the update are lost. The apps keep talking to it, since 0.11.0 speaks protocol 11 too. Don't start 0.11.0 by hand on the updated data: T3 Code 0.1.13 moved the engine's data forward, and an older engine would start on it and fail on what it cannot read. 0.12.0 refuses to start an engine older than the newest one that ran on the data, and 0.11.0 refuses a database with these migrations: either way the server exits with status 78 and says to run `j3-bots update --rollback`.

## What's new

### Routines in steps

- **A routine can be several steps, each done by a bot** ([#362](https://github.com/JPSAUD501/j3-bots/pull/362)): "every Monday, gather my emails, have Atlas draft the replies, and ask me before Wren sends them". Ask a bot for one in its conversation. A one-step routine works as before.
- **Each step is that bot's own work**, with its instructions, memory, tools and permission mode, and gets what the steps before it reported. A step can end the run quietly when its condition doesn't hold.
- **A step can wait for your yes.** You get a notification, and the run's card shows the question, its two answers, a note for the bot and the time left. It waits no later than the routine's next run.
- **Drawn as a track:** one stop for what starts the routine and one for each step, with its bot's face. Each run's card moves along as the run does and folds to one line when it ends ("Done · 3 replies sent"). A failure says what happened, and **Try again** goes on from the step that failed. Stop reaches the step at work, whichever bot runs it.

### Documents open in the app

- **PDF, text, Markdown, CSV, Excel, Word and PowerPoint files open in the app's own viewer** ([#352](https://github.com/JPSAUD501/j3-bots/pull/352)), as images do, on the web, the desktop and Android. Their card shows a small preview and says what the file is: "PDF, 12 pages", "Spreadsheet, 3 sheets".
- **A PDF shows every page as laid out.** A spreadsheet shows each sheet's values as Excel does; formulas never run. Word and PowerPoint show text, lists, tables and pictures, without their layout. A file too big or damaged says so and offers **Save**.

### Quick access brings the window you were in

- **Opened by the shortcut over another app, quick access shows that app and its window's title above the composer** ([#354](https://github.com/JPSAUD501/j3-bots/pull/354)), and the bot gets them with your message. × takes them off.
- **A picture of that window, when you ask**: tap its chip. Settings → Devices, under This device, has "Include the window's title" (on) and "Add a picture of the window" (off). On macOS, it needs Screen Recording allowed.
- **Only what the chips show goes**, with that one message. Nothing is read in the background. The message keeps "Looking at …" under it.

### Effort, beside the model

- **Each bot has an effort** ([#358](https://github.com/JPSAUD501/j3-bots/pull/358)) when you edit it: Default, and the levels the AI offers for its model. More effort takes longer and uses more of your plan. Every bot starts at Default, which lets the AI decide.
- **A model change never keeps a level the new model doesn't take**: before Save, the form says "GPT-5.5 Codex doesn't offer Max, so Scout uses Default".

### One card for a sign-in

- **A bot asks for every value at once** ([#357](https://github.com/JPSAUD501/j3-bots/pull/357)), as "Sign in to Mail: email, password". A secret value is masked, with an eye to show it. A password manager fills a sign-in, and is kept away from an API key.
- **The card says where the values go**: used without being seen, or "kept out of this conversation, in a private file your bot can read for the next 24 hours". A value too long is kept whole, never cut, and the card says so.

### When a bot asks before acting anyway

- **A bot in Auto or Full access whose AI asks before each action anyway says why** ([#356](https://github.com/JPSAUD501/j3-bots/pull/356)), once for each model, in its conversation, with what to do. The engine's own words are under **Details**. The engine's other notices, which leave you nothing to do, go to the server's log only.

### The engine and the icon

- **J3 Bots pins T3 Code 0.1.13** ([#353](https://github.com/JPSAUD501/j3-bots/pull/353)). A Codex command's approval card no longer repeats the command as its reason, and pushing a pull request with changed push hooks asks you first, even in Full access.
- **A new icon, "j3" with a bot's light on** ([#351](https://github.com/JPSAUD501/j3-bots/pull/351)): the dot of the j is a bot's light, on the window, installers, Android, the browser and the tray, where it takes the waiting color and grows while something waits for you.

## Known limits

**Not tried for real yet:**

- **The Android app** didn't run on a phone: routines in steps, documents, effort, the sign-in card and its autofill, the notice and the icon were checked by their tests and types only.
- **Quick access reading the window on macOS and Windows**: written from their documented APIs, never run. On Linux it ran on X11 without a compositor; a picture on a composited desktop was not tried.
- **Against a real engine or real AIs**: effort, the two notices, the sign-in card and routine steps were checked against T3 Code's source and the scripted engine, and the eval cases for the new instructions were not run. No real password manager filled the card.
- **The new icon** was compared with its drawing, not seen in a tray, launcher, installer or browser tab. PDFs were not opened in the packaged desktop app.

**Limits of this version:**

- **Desktop quick access doesn't draw the track**, and a step's plan and little ones are not shown. A bot's details don't list the routines of other bots it takes part in.
- **A routine deleted while a step's turn is starting** leaves that turn to finish, with nothing after it.
- **On Wayland, quick access reads no window.** On X11 without a compositor, it takes no picture.
- **Only you change a bot's effort**: a bot made by another bot starts at Default. A level its model stops offering after the AI updates stays saved, and the bot works at Default meanwhile.
- **A sign-in card's value is one line**, so a key that spans lines loses its line breaks. A question card still asks for an answer to every question, optional ones too.
- **Old Office files and OpenDocument** still open in another app. Text in a PDF can't be selected, and it shows up to 500 pages.
- **An import run by a release from before 0.12.0**, onto data a newer engine ran on, skips the engine check.

Everything listed under "Known limits" in the [0.11.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.11.0) notes still applies.
