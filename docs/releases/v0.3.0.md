# J3 Bots 0.3.0

**Draft.** The notes for the 0.3.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

Your bots can now live on your own computer. On Linux and Windows the desktop app runs J3 Bots itself: one click on its first screen, no server to install, no address and no pairing code. Claude Code and Codex are signed in from the app, a routine the computer slept through is made up only while that still makes sense, and an app update moves your bots to the server it carries. It still pins T3 Code 0.1.11.

## Updating

This release still speaks **protocol 7**, so a 0.2 app and a 0.3 server work together, in either order.

- **The server:** `j3-bots update`. It copies the databases first and runs two migrations (0021 and 0022: missed routines and roster sections). `j3-bots update --rollback` puts back 0.2.0 and the databases as they were before the update.
- **The desktop app:** the AppImage and the Windows install update themselves. The deb and the Mac build link to this release.
- **The web client** comes with the server.
- **The Android app:** install `j3-bots-0.3.0-android-arm64.apk` over the old one; it keeps its pairing. A 0.2 Android app keeps working against a 0.3 server, but it doesn't show a routine's missed runs or that a run started late, and it lists every bot without sections.

### A name other than an address now gets 403

Over plain HTTP, the server answers only at `localhost`, at an IP address, or at the name in `publicOrigin` ([#156](https://github.com/JPSAUD501/j3-bots/pull/156)). A browser that opens it as `http://<machine>.local:3737`, or any other name, now gets **403**: a web page on a name its owner points at your machine could otherwise talk to the server as its own page. The browser shows one line saying which addresses work, and the server's log names the refused name and what would serve it ([#163](https://github.com/JPSAUD501/j3-bots/issues/163)).

- **At home:** open the server at its address, as `j3-bots pair` prints it.
- **Behind a proxy or tunnel over plain HTTP that passes its own name through:** set [`publicOrigin`](https://github.com/JPSAUD501/j3-bots/blob/v0.3.0/docs/operations/exposing.md#publicorigin) to that address and restart the service.
- **Over HTTPS** nothing changes: the name isn't checked there.

Pairing also takes only a JSON request now, so a web page can no longer lock it with wrong codes. Every J3 Bots client already sends JSON.

## What's new

- **Use this computer** ([#155](https://github.com/JPSAUD501/j3-bots/pull/155), [#157](https://github.com/JPSAUD501/j3-bots/pull/157), [#158](https://github.com/JPSAUD501/j3-bots/pull/158), [#160](https://github.com/JPSAUD501/j3-bots/pull/160), [#164](https://github.com/JPSAUD501/j3-bots/pull/164), [#214](https://github.com/JPSAUD501/j3-bots/pull/214)). On Linux x64 and Windows x64, the desktop app's first screen asks where your bots live. "Use this computer" goes straight into meeting your first bot: the app carries its own server, starts it, and signs this computer in without a code. The bots sleep when the computer sleeps. Closing the window keeps them running in the tray; Quit stops them. "Connect to a server" is the address and pairing flow you know. Settings changes the choice both ways, and can start the app with the system. Your bots' data stays on this computer, in the app's own folder, apart from a server installed from the command line.
- **Sign in from the app** ([#166](https://github.com/JPSAUD501/j3-bots/pull/166)). On this computer, the step that connects a model offers "Sign in with Claude" and "Sign in with ChatGPT (Codex)" for each harness it finds. The sign-in opens in your browser and goes into J3 Bots' own home for that harness, never your own `~/.claude` or `~/.codex`. An endpoint, as before, works too, from the same step.
- **Missed routines** ([#162](https://github.com/JPSAUD501/j3-bots/pull/162)). A routine that came due while J3 Bots wasn't running runs when it's back only while it's nearer to the missed run than to the next one; otherwise it waits for the next and counts what it missed. A daily 8:00 routine runs at 10:00, and is skipped at 7:00 the next morning. The routine says "Missed 1 run while J3 Bots wasn't running", a late run says how late, and the bot is told when its run was due. A one-time routine always runs.
- **The app updates the server it runs** ([#161](https://github.com/JPSAUD501/j3-bots/pull/161), [#177](https://github.com/JPSAUD501/j3-bots/pull/177)). When an app update brings a new server, the first start takes a snapshot of your bots' data, starts the new server and waits for it. If it never gets ready, the app puts the snapshot back, starts the old server again and says so, with Try again.
- **The engine's first download shows its progress** ([#159](https://github.com/JPSAUD501/j3-bots/pull/159)).
- **Organize your bots** ([#169](https://github.com/JPSAUD501/j3-bots/pull/169), [#176](https://github.com/JPSAUD501/j3-bots/pull/176), [#172](https://github.com/JPSAUD501/j3-bots/pull/172)). Sections of your own, pinned bots at the top, hidden bots, Mark as unread, and a menu on each bot: right-click or "…" on the web and the desktop, a long press on a phone. Every device shows the same arrangement.
- **Bot templates** ([#170](https://github.com/JPSAUD501/j3-bots/pull/170)). Share a bot as a `.j3bot` file, with its profile, job, skills and routines, and create a new bot from one. Its memory, its conversation and your accounts never go in the file.
- **Files where you put them** ([#173](https://github.com/JPSAUD501/j3-bots/pull/173)). A file or image you attach stays where you placed it in your message, as a chip that opens it.
- **Stop moves to the details** ([#182](https://github.com/JPSAUD501/j3-bots/pull/182)). The conversation shows what a bot is doing without a button to end it. "Stop what it's doing" is one press away, in the bot's details, and `Ctrl+.` (`⌘.`) still stops it.
- **Type for touch and pointer screens** ([#171](https://github.com/JPSAUD501/j3-bots/pull/171)). Text sizes measured for each kind of screen, so the web on a phone reads like the Android app, and a line that introduces a teammate's message.
- **Your first bot asks what to call you** ([#175](https://github.com/JPSAUD501/j3-bots/pull/175), [#179](https://github.com/JPSAUD501/j3-bots/pull/179)), and saves it for every bot. Only your own words count.
- **Bots keep their engine apart from yours** ([#165](https://github.com/JPSAUD501/j3-bots/pull/165), [#174](https://github.com/JPSAUD501/j3-bots/pull/174)). No harness the engine runs writes your own `~/.claude`, `~/.claude.json` or `~/.codex`, and on Linux and macOS a Codex bot is no longer offered your `~/.agents/skills`. A bot also knows the T3 Code it runs on is J3 Bots' own, not yours.

## Use from your phone

Settings → "Use from your phone" ([#208](https://github.com/JPSAUD501/j3-bots/pull/208)) lets a phone on the same network reach the bots on this computer. Turn it on, press "Pair a phone" and scan the QR code: the phone opens the app with the address and code filled in. Each code lasts five minutes. It's off by default.

- **A network you trust only.** The connection is plain HTTP, so don't turn it on on café or hotel Wi-Fi. If the computer has a public address, the app keeps the bots on the computer alone and says why.
- **Turning it on or off restarts your bots.** If a bot is working, the app asks first. Paired phones stay paired while it's off and reconnect when it's back on.
- **The firewall.** On Windows, the first time it's turned on, Windows asks whether "Node.js JavaScript Runtime" may use the network: allow it on private networks. On Linux, Settings shows the `ufw` command when one is needed.
- **The bots run only while the computer is awake.**

## Known limits

- **Outside your home network**, a phone can't reach the bots on your computer. That is a later step.
- **macOS:** the app can't run your bots on a Mac yet. On Apple silicon it is built but not offered until it has run on a real Mac; on an Intel Mac, connect to a server.
- **On Windows, a Codex bot is offered your own skills** from `%USERPROFILE%\.agents\skills` ([#168](https://github.com/JPSAUD501/j3-bots/issues/168)). Codex finds that folder through Windows' profile folder, which nothing J3 Bots can set changes, and no Codex release has a setting that turns only it off. Claude Code bots aren't affected. Until Codex offers a way, keep skills you don't want bots to use out of that folder, or use Claude Code for those bots.
- **Signing in with a subscription** from the app has been tested up to the sign-in page, not completed with a real account. An endpoint is the tested way to reach the models ([open question 2](https://github.com/JPSAUD501/j3-bots/blob/v0.3.0/docs/open-questions.md#2-does-a-subscription-sign-in-work-inside-a-j3-owned-provider-home)).
- **Start with the system** has not been seen starting the app at sign-in on Windows or a Linux desktop.
- **The provider key** still reaches the commands a bot runs, and a Codex shell snapshot written before this release, which held it, stays in a home that was upgraded ([Security: secrets](https://github.com/JPSAUD501/j3-bots/blob/v0.3.0/docs/architecture/security.md#secrets)).

Everything listed under "Known limits" in the [0.2.0 notes](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.2.0) and "Known not to work yet" in the [0.1.0 notes](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.1.0) still applies, except what this release changed: the server now runs on Windows, as the desktop app's own; the app sets up providers for the bots on its computer; and the engine no longer writes into your own harness folders.
