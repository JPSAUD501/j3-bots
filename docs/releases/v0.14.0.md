# J3 Bots 0.14.0

**Draft.** The notes for the 0.14.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

You can reply to a message, quote the words you mean, and mention your other bots and rooms in a bot's conversation. You can dictate a message, and on the desktop, record your screen for a bot. A connector's app is part of the bot's reply, and goes full screen or stays pinned at the top. A bot's little ones stay in sight after it answers, and What's new says what each update brought. J3 Bots now sends anonymous usage data, which you can turn off in Settings, and turns off T3 Code's own analytics. A diagnostics file you can download helps whoever helps you. It still pins T3 Code 0.1.13.

## Updating

This release speaks **protocol 11**, as 0.9.0, 0.10.0, 0.11.0, 0.12.0 and 0.13.0 do, so an app and a server on any of them keep talking in either order. Update the server first anyway: everything new needs it, replies and quotes, mentions in a bot's conversation, a connector's app in the reply, dictation, screen recording, little ones after the reply, the Privacy area and its usage data and diagnostics. Then update the apps.

An app older than 0.14.0 shows a message without what it quotes, and the bots and rooms a conversation's message mentions as plain names. It shows a connector's app shown from now on as a line that asks for a newer version of the app, while the apps it showed before stay under their turn's work. It has no microphone and no Settings → Voice, no Privacy area, so it cannot turn usage data off or download diagnostics, and no way to record the screen: it shows a bot's offer to record as the message alone, and a recording as a file. It folds a turn's row as the turn ends, with its little ones gone, as before.

**Usage data is on once the server is updated.** The server sends anonymous usage data to J3 Bots' project on PostHog from its first start on 0.14.0: which features get used, which harnesses and models bots run on, whether turns finish and updates land. It never holds anything you or your bots wrote, named or own. To keep it off from the start, set `DO_NOT_TRACK=1` or `J3_TELEMETRY_ENABLED=false` in the server's environment before you update ([Operating: usage data](../operations/operating.md#usage-data)); afterwards, turn it off in Settings → About and updates → Privacy on an updated app. [Usage data](../product/usage-data.md) lists every event.

**T3 Code's own analytics are now off.** Before 0.14.0, the engine J3 Bots runs sent T3 Code's own product analytics to T3 Code's makers, as T3 Code does by default, and its tracing followed the same switches (**Read** in T3 Code 0.1.13's source, `AnalyticsService.ts` and `otelEnvironment.ts`). J3 Bots installs sent them too. From 0.14.0, J3 Bots always starts the engine with both turned off, whatever the server's environment says.

- **The server:** from an app, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases, the engine's too, into a snapshot first, then runs this release's migrations:
  - **0063** keeps a connector's app as an entry of the conversation or room where the bot used it, with the turn that opened it, and what an app tells its bot, one for each app. Apps shown before stay where they were, under their turn's work.
  - **0064** keeps dictation's settings, one set for the server and every device: where speech becomes text, the language, the words to spell right, taking out filler words (on), tidying up with the AI (off), and the chosen models. A cloud service's key is kept in Secrets, not here.
  - **0065** keeps the usage data switch, on; the install's random id, which leaves the server only scrambled; and the events sent, for See what is sent.
- **The desktop app and the Android app** update themselves as they open, or from the prompt every paired app shows. The deb and the Mac build link to this release. Android asks for the microphone the first time you dictate, and so does macOS for the desktop app; on a Mac, recording the screen asks for Screen Recording and Accessibility too.
- **The web client** comes with the server.

The server now also keeps its own log in `~/.j3-bots/logs/server.log`, at most five files of 4 MiB, which the diagnostics file reads. The first dictation on the server downloads its speech model once, 751 MB.

### Rolling back

`j3-bots update --rollback` to 0.13.0 puts back the databases from the snapshot, the engine's included, so the messages, quotes, apps shown, dictation settings and the usage data switch changed since the update are lost. The apps keep talking to it, since 0.13.0 speaks protocol 11 too. Both releases pin T3 Code 0.1.13, so the engine's data is not moved forward. 0.13.0 refuses a database with these migrations: started by hand on the updated data, the server exits with status 78 and says to run `j3-bots update --rollback`.

0.13.0 sends no usage data of J3 Bots' own, but it starts the engine as releases before 0.14.0 did, so T3 Code's own analytics are on again until you update.

## What's new

### Reply, quote, and mention

- **Reply to a message, quote the words you mean, and mention your other bots and rooms in a bot's conversation** ([#379](https://github.com/JPSAUD501/j3-bots/pull/379), [#378](https://github.com/JPSAUD501/j3-bots/pull/378)).
  - **Reply** is beside React on the web and the desktop, and in a message's long press on Android, where swiping a message to the right replies too. The composer shows "Replying to Wren" with the start of the message.
  - **Quote** a passage: select words in one message and press Quote; on Android, Quote part in the message's menu. A message quotes up to three messages of the same conversation or room, one of them whole. Each shows as a card above it, and a tap goes to what it quotes.
  - **In a room, replying to a bot's message speaks to that bot**, unless the message mentions someone. A bot can reply to a message too, rarely.
  - **In a bot's conversation, `@` names your other bots and the rooms that bot is in.** "Ask @Wren for the photo" or "tell @Launch week it's in": the bot knows which one you mean, and asks, passes it on, posts or reads as you asked. A mention itself wakes and tells no one. A tap on a name in any message opens that bot or room.

### Dictation

- **Dictate a message: tap the microphone beside Send and talk** ([#382](https://github.com/JPSAUD501/j3-bots/pull/382)).
  - The words appear where the cursor is as they are heard, the ones still changing lighter. Tap again to stop, or Esc (Back on Android) to put the message back as it was. Nothing is sent by itself. Ctrl+Shift+Space does the same on a computer (⇧⌘Space on a Mac).
  - **Where speech becomes text is yours to choose**, in Settings → Voice. Automatic: on an Android phone that knows the language, the phone itself; anywhere else, your J3 Bots server, with the engine's own speech recognition and a model that runs there. The voice leaves your machines only when you pick OpenAI, xAI or OpenRouter and give it your key, which Secrets keeps. Audio is never stored.
  - Settings → Voice also holds the language, words to always spell right, taking out filler words such as "um", and, under More, the speech model and tidying up with the AI, which spends your AI's allowance.
  - The server dictates one at a time. The first dictation gets it ready once, and says how far the download got.

### A connector's app, in the reply

- **A connector's app is part of the bot's reply, and goes full screen or stays pinned at the top while you chat** ([#381](https://github.com/JPSAUD501/j3-bots/pull/381)).
  - It stands where the bot used the service, between what the bot said before and after, under a light header with **Show full screen**. In a room, it is in the room.
  - **Full screen** covers the conversation and keeps its composer. What the bot says meanwhile slides up over the app, to read or hide. The close control, Esc or Back puts it back.
  - **Pinned**, when the app asks for it, it stays at the top of the conversation while you scroll, and its place in the reply has **Put it back here**. The app is never loaded again as it moves.
  - **What you do in it can reach the bot** the next time it answers there, as the service's words, never yours. It wakes no one.
  - An app can offer files to save; nothing is saved until you press Save. It cannot write to your clipboard.

### Recording the screen for a bot

- **On the desktop, record your screen for a bot: it gets one file, and decides what to do with it** ([#388](https://github.com/JPSAUD501/j3-bots/pull/388)).
  - **Record your screen** is under `+` in the composer, in the desktop app and its quick access. A bot can offer it under its message too; in a browser and on Android, the offer says to open the app on the computer.
  - **A sheet says first what is recorded**: every screen, your voice, and the keys you press and where you click, or on Wayland the screen you share and your voice. It counts 3, 2, 1.
  - **While it records**, a small control floats over everything, with the bot's face listening, a red dot and no clock, Pause, Stop and Discard. Pause records nothing, keys and clicks included. Where macOS or Windows say a password field has the keys, only that a password was typed is kept; Linux doesn't say, so the sheet tells you to pause.
  - **On Stop, the recording is in your message** as one zip: the videos, the voice, what was clicked and typed, a picture at each click, and a guide for the bot's AI. Nothing leaves the computer while it records. It uploads to your server as any file does, in pieces that resume, up to 8 GiB as the server's disk allows, and the bot gets it when you send.

### Privacy: usage data and diagnostics

- **J3 Bots sends anonymous usage data, and you can turn it off in Settings → About and updates → Privacy** ([#385](https://github.com/JPSAUD501/j3-bots/pull/385)).
  - It tells the people who make J3 Bots which features get used and what goes wrong. Only your server sends it, from a fixed list of events whose every detail is a word from a fixed list, a yes or no, a rough count or a version, checked as it leaves.
  - **Never sent**: messages, names, memory, files, paths, addresses, IP addresses, emails, ids of your bots, rooms or conversations, secrets, what an app shows, or the text of an error.
  - **See what is sent** shows the last 100 events exactly as they left. One switch turns it off for the whole server, at once, and drops what waits.
  - **T3 Code's own analytics are always off** now, in the engine J3 Bots runs. Before 0.14.0 the engine sent them by default (see Updating).
- **Download a diagnostics file for whoever helps you, from Settings → About and updates → Privacy** ([#387](https://github.com/JPSAUD501/j3-bots/pull/387)).
  - A sheet says what it holds: the server's and the engine's logs of the last 7 days, what failed and when, versions, settings and counts, and the usage data sent. And what it never holds: your messages, names of bots, rooms or people, passwords, keys or other secrets.
  - Web and desktop save the file; Android shares it. On the server's machine, `j3-bots diagnostics` writes the same file, for when no app opens.

### Little ones, after the reply

- **A bot's little ones stay in sight after it answers, until each one is home** ([#380](https://github.com/JPSAUD501/j3-bots/pull/380)).
  - The turn's row keeps the bot's face, "Working" and its little ones, each saying what it does, and each goes back into the bot as it ends. Once the last is home, the row folds into "Worked · 5 steps".
  - The roster's dots count them too, through the bot's next turn.

### What's new

- **What's new says what each update brought, in your language** ([#384](https://github.com/JPSAUD501/j3-bots/pull/384)).
  - On the web and the desktop, it is a row above Settings in the list's footer; on Android, the last row of Settings. After an update, it reads "New in 0.14" until you open it. Nothing opens by itself.

## Known limits

**Not tried for real yet:**

- **The Android app** didn't run on a phone: everything new in it was checked by its tests and types only. Its swipe to reply, the quote sheet, an app moving between the reply, full screen and pinned, the phone's own speech recognition and sharing the diagnostics file are unseen.
- **The desktop app** was not run. No full recording went through the packaged app, nor on macOS or Windows: their permissions, leaving the control out of the capture, and the password signals (macOS's secure input, Windows' UI Automation) are **Assumed**. No multi-GB recording was uploaded, and no disk filled.
- **In a browser**, the Quote button's place, a quote card's jump and its light were not seen.
- **Dictation** ran against the real engine directly, not through J3 Bots end to end, and no real microphone was used on any client. The fit on a 4 GB Raspberry Pi is worked out from a laptop's numbers.
- **Usage data** was sent to a fake capture server only, never to the real project.
- **The engine's trace file** in the diagnostics file was read in T3 Code's source, not on a running engine; that T3 Code's warnings never carry conversation text is **Assumed**.
- **Against real AIs**: nothing ran. Whether bots follow mentions, use `reply_to` sparingly, read an app's context or offer a recording as meant had no real-model eval. The little ones after the reply rest on T3 Code's source, **Read**, not on a live turn.

**Limits of this version:**

- **Quotes** stay in one conversation or room, at most three per message; J3 Bots' own messages can't be quoted, and bots quote no passages.
- **A mention goes by the name a bot or room has now**: one renamed since reads as plain text in older messages.
- **Dictation** runs one at a time on a server. On Android, the phone's own recognition needs Android 13 or later with the language installed.
- **A connector's app** shows only inline in quick access. An app that needs `eval`, WebAssembly or more than 2 MiB doesn't run, as under any host that follows the spec's rules.
- **A recording** has no transcript yet: the voice is only in its audio. Typed text is read as a US keyboard makes it. On Linux the control shows in the video. A recording taken out of a message unsent stays on the server, as any uploaded file does.
- **Usage data** counts a device's connection again after the server restarts that day.
- **The diagnostics file** holds no log of the apps' own, since they keep none.
- **What's new** is not in quick access.

Everything listed under "Known limits" in the [0.13.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.13.0) notes still applies.
