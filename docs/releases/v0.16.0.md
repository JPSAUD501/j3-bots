# J3 Bots 0.16.0

**Draft.** The notes for the 0.16.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

J3 Bots has its own browser. While the app is open on your computer, your bots browse there, in a real browser on your own connection; when no computer is open, they browse in the server's browser. The desktop app is a browser you use yourself too, beside the conversation or in its own window, with a private tab no bot sees. Your sign-ins are kept sealed and carried between your computer and the server, and Settings → Browser lists them. Several bots can share a tab and take turns, you take it just by using it, and each bot's pointer carries its face and name. It still pins T3 Code 0.1.13.

## Updating

This release speaks **protocol 11**, as 0.9.0 to 0.15.0 do, so an app and a server on any of them keep talking in either order. Update the server first anyway, then the apps: a computer's app browses for the bots only from 0.16.0 on.

An app older than 0.16.0 is no browser for the bots: while only such apps are open, the bots browse in the server's browser. It has no browser of its own, none of the tabs you open, no live view to take over and no list of sites in Settings → Browser. That it still shows a bot's page as 0.15.0 did is **Assumed**: no app older than 0.16.0 ran against this server.

**Your sign-ins move over once.** Until 0.16.0, bots browsed in the engine's browser. As 0.16.0 first starts, it moves the sites signed in there into its own sign-ins, sealed, in the background: you stay signed in where you were. Then it deletes the engine's browser and what it kept. If that browser is not there, or what it kept cannot be read, the server logs a warning, leaves both as they are, and tries again at its next start ([Operating: the browser](../operations/operating.md#the-browser)).

**The server's browser downloads the first time a tab opens on it.** It is Chrome for Testing, about 210 MB (413 MB unpacked), into `browser/chrome/` in the data directory; the machine must reach Google's storage then. On Linux it also needs a sandbox the system allows, a few shared libraries and fonts: run `j3-bots doctor`, which checks them under **Browser** and prints the commands that fix what is missing, and run it again after a tab first opened there. Until then, bots browse only while the app is open on a computer, and a bot's details say the machine needs setting up ([What the machine needs](../operations/browser-secrets-and-connectors.md#what-the-machine-needs)). The server the desktop app starts on your own computer runs no browser of its own: its bots use the app's.

- **The server:** from an app, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases, the engine's too, into a snapshot first, then runs this release's migration, with nothing for you to do:
  - **0072** keeps every tab the bots and you opened, with where it came from and the bots on it, so a tab is still there after a restart. A private tab is never kept. A browser card a bot had open closes on its own.
  - The sign-ins are a file of their own, `browser/signins.sqlite`, sealed under the secrets' key. It is outside the update's snapshot, and in the backup ([Operating](../operations/operating.md)).
- **The desktop app and the Android app** update themselves as they open, or from the prompt every paired app shows. The deb and the Mac build link to this release.
- **The web client** comes with the server.

### Rolling back

`j3-bots update --rollback` to 0.15.0 puts back the databases from the snapshot, the engine's included, so the tabs, rooms, messages and settings changed since the update are lost. The apps keep talking to it, since 0.15.0 speaks protocol 11 too. Both releases pin T3 Code 0.1.13, so the engine's data is not moved forward. 0.15.0 refuses a database with this migration: started by hand on the updated data, the server exits with status 78 and says to run `j3-bots update --rollback`.

The rollback leaves the sign-ins file as it is, and 0.15.0 does not read it. The engine's browser that 0.16.0 deleted is not in the snapshot, so on 0.15.0 the bots browse in the engine's browser again, signed out of every site: sign in again there. A 0.16.0 desktop app against a 0.15.0 server browses for no bot.

## What's new

### J3 Bots' own browser

- **Your bots browse in J3 Bots' own browser: on your computer while the app is open there, and on the server when none is** ([#405](https://github.com/JPSAUD501/j3-bots/pull/405), [#406](https://github.com/JPSAUD501/j3-bots/pull/406), [#409](https://github.com/JPSAUD501/j3-bots/pull/409)).
  - On your computer, a bot's tab opens in the desktop app you used last: a real browser, on your connection, so sites see what they would see for you. With no computer open, it opens in the server's browser, which keeps up to three pages open at once and sets the least used one aside past that; it opens again where a new tab would, the next time a bot uses it, and the bot is told.
  - The engine's own browser is off for every bot. Bots browse only through J3 Bots.
  - A bot whose browser you turn off, or that you delete, leaves every tab it was on.

### The desktop app's browser

- **The desktop app is a browser you use yourself, beside the conversation or in its own window** ([#409](https://github.com/JPSAUD501/j3-bots/pull/409)).
  - The globe in a conversation's header, a room's too, opens it beside the conversation. Drag the divider to share the room, double-click it to split it in half, or drag it far enough to close the browser, which opens again at the width it had. **Open in a window** gives the browser a window of its own; closing that window brings its tabs back beside the conversation.
  - Tabs, back and forward, an address bar that suggests your open tabs, then the sites you visited, then a search, zoom, find in the page, downloads, history, print, **Reopen closed tab**, and a browser's shortcuts, which work while the page has the keys. A new tab shows the sites you visit most, and a page that didn't open says why in everyday words, with Try again.
  - **A private tab is yours alone.** No bot sees it, it stays out of your history, and it forgets everything when it closes.
  - The browser asks for nothing it doesn't need: no camera, microphone, location or notifications.

### Sign-ins

- **Your sign-ins are kept sealed and carried between your computer and the server's browser; Settings → Browser lists the sites that keep data** ([#408](https://github.com/JPSAUD501/j3-bots/pull/408), [#409](https://github.com/JPSAUD501/j3-bots/pull/409)).
  - Sign in once, on your computer or the server's browser, and you and every bot stay signed in on the other: J3 Bots carries a site's cookies and what it keeps in the browser, its databases too within limits. A site too big to carry is marked "Too big to carry between browsers" and stays signed in where it is.
  - The sign-ins are sealed under the secrets' key, so the file names no site. While the secrets are locked, Settings says so.
  - **Settings → Browser** lists the sites that keep data, whose cookies and site data J3 Bots carries between your browsers, each with **Clear data**, then **Clear data of all sites**, which asks first and signs you out wherever you were signed in. Clearing reaches the server and every computer, at once on those connected and first thing on one that connects later; open tabs stay open, signed out.
  - The sites bots signed in to before 0.16.0 move over once, as the server first starts.
  - A bot types a saved login into the page without ever seeing the password, and only in the field it was meant for. Your keys and clicks wait until it is done: the page says "A bot is signing in here. The page is yours again in a moment."
  - A computer you remove from Devices loses its sign-ins.

### Working together on a tab

- **Several bots can share a tab and take turns, and you take it just by using it** ([#406](https://github.com/JPSAUD501/j3-bots/pull/406), [#407](https://github.com/JPSAUD501/j3-bots/pull/407)).
  - The bots on a tab act one at a time; a bot whose turn it is next waits a moment rather than being refused.
  - **Touching the page is using it.** There is nothing to press first: a click, a tap, a key or scrolling reaches the page at once, and the bots wait until 10 seconds after your last input. Pointing, reading and zooming don't make them wait.
  - On the web and Android, **Wait for me** holds the tab for you until you press **Continue**. Leaving the browser gives it back.

### Seeing your bots at work

- **Each bot's pointer moves on the page in its colour, with its face and name** ([#407](https://github.com/JPSAUD501/j3-bots/pull/407), [#415](https://github.com/JPSAUD501/j3-bots/pull/415), [#409](https://github.com/JPSAUD501/j3-bots/pull/409)).
  - The arrow glides in the bot's colour; a tag with its face and name shows while it moves and at a click. It bobs while the bot thinks, its face smiles at a click, perks up when you take the tab, then waits, and the pointer steps aside while the tab is yours. Under reduced motion it moves at once. In a tab on the desktop app, the page draws the pointer itself, and there it moves only when the bot acts and its face stays still, so a page that isn't changing sends no new pictures.
  - The faces of the bots on a tab sit on the tab, and one quiet line by the address says who is there and who is acting.
  - A bot never sees its own pointer: its pictures of the page are taken without it.
- **On the web and Android, watch the page live and take it over by touching it** ([#407](https://github.com/JPSAUD501/j3-bots/pull/407)).
  - On a wide screen the page sits beside the conversation. On a phone, and in a narrow window, the end of a bot's conversation shows its page live, in small, and **See the browser** brings you back to it; a press opens the live view, over the whole screen on a phone and over the conversation on a tablet.
  - The live view has the bar in your thumb's reach, a sheet with **Wait for me** and a reply to the bot, every tab in a grid where a closed tab comes back with **Undo**, a swipe to the next tab, and **Follow** on a wide page.
  - While a bot waits for you, the web page's title starts with "(needs you)".

### When a tab can't open

- **A tab that can't open says why, and a computer that disconnects shows at once** ([#414](https://github.com/JPSAUD501/j3-bots/pull/414)).
  - Opening a tab says why it didn't open, and what you can do where there is something: no browser can open one now, the server's is full, or the page didn't load in time, failed or was refused.
  - When the computer that runs a tab disconnects, its page stops on the last picture and one line names it: "Laptop disconnected". What you do there isn't sent, and the line says "Not sent" once.

## Known limits

**Not tried for real yet:**

- **The Android app** didn't run on a phone: the live card, the live view, its tab grid, swipes and sheet, and the pointer's glide were checked by tests and types only.
- **The web viewers** ran only in the gallery, in a headless browser at phone and tablet widths, never against a real server.
- **The desktop app's browser** ran only on Linux, in checks against pages made for them; nothing ran on macOS or Windows, and no one used it day to day.
- **The server's browser** ran on Linux only; on Windows and macOS it is **Assumed** to need nothing installed. A Raspberry Pi was not measured: expect it to be slower, and keep to one or two pages at a time.
- **The move of the sign-ins** was tried on a made-up profile, not on a server that browsed on 0.15.0.

**Limits of this version:**

- **The desktop browser** has no bookmarks or extensions yet. Tabs cannot be dragged between the panel and the window, or reordered.
- **A sign-in a site keeps only while it is shown inside another site's page** is not carried between browsers.
- **Bringing sign-ins in from Chrome or Firefox** comes later.
- **A computer that disconnects** keeps its tabs for 45 seconds before they are set aside, and opened again elsewhere when a bot next uses them.
- **On a phone lying on its side,** the live view's bar is a column at the end edge, whichever hand holds it.

Everything listed under "Known limits" in the [0.15.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.15.0) notes still applies.
