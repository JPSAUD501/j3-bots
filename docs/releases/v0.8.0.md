# J3 Bots 0.8.0

**Draft.** The notes for the 0.8.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

A machine with neither Claude Code nor Codex now goes from nothing to a working bot without a terminal: J3 Bots says why a provider can't run, installs its own copy of a missing harness from its maker, and keeps the harnesses up to date. Bots also get people's names, as on a team. It still pins T3 Code 0.1.11.

## Updating

This release speaks **protocol 10**, as 0.6, 0.7.0 and 0.7.1 do, so apps and server of these versions work together: update them in any order. An app older than 0.8.0 shows a provider it can't run as "Unavailable now", as before, without the cause or the Install button.

- **The server:** from any device, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases into a snapshot first, then runs this release's one migration, **0036**, which adds the setting that turns the harness updates off (on by default).
- **The desktop app and the Android app** update themselves as they open. The deb and the Mac build link to this release.
- **The web client** comes with the server.

### Rolling back

`j3-bots update --rollback` to the release you updated from puts back the databases from the snapshot, so the messages made since the update are lost with the rest of the database. The harness copies the server installed stay in its data directory, and an older server doesn't use them: it runs the harnesses on its `PATH` as before. Don't start 0.7.x by hand on the updated data: it refuses a database that has migration 0036, and says to roll back.

## What's new

- **Why a provider can't run, and what fixes it** ([#274](https://github.com/JPSAUD501/j3-bots/pull/274)). "Unavailable now" now says which: not installed on this computer (or on the server), found but failed to start, or turned off, with the engine's own words and one action: **Install**, **Try again** or **Look again**. In the first run, **Create** waits while no provider can run a bot, instead of failing with an error the screen already predicted. `j3-bots doctor` names the cause and the fix.
- **J3 Bots installs Claude Code and Codex itself** ([#277](https://github.com/JPSAUD501/j3-bots/pull/277)). On a provider that isn't installed, **Install** downloads the harness from its maker (`downloads.claude.ai`, `releases.openai.com`), checks it against the maker's SHA-256 before anything runs, keeps it in the server's data directory, and runs the provider on it. The app shows the download's progress, with **Cancel**, and a failure says why, with **Try again**. A harness you installed yourself stays yours: J3 Bots never installs beside it nor touches it.
- **The harnesses stay up to date** (#277, [#276](https://github.com/JPSAUD501/j3-bots/pull/276)). About every six hours the server looks for a newer version of its own copies and installs it by itself; a new version waits until no bot is running anything on that provider, and each bot's next turn picks it up, with its conversation. Settings → Engine shows each harness's version and the newest, **Update** when one is out, and how the last update ended; one switch turns the updates by themselves off. For a harness you installed, **Update** asks the engine to update it the way T3 Code does.
- **Bots get people's names** ([#281](https://github.com/JPSAUD501/j3-bots/pull/281)). A bot naming a teammate picks a first name common where you are, fitting its character more than its job, and different from the team's other names; the job goes in the title. The first run suggests a person's name in the app's language. A name you give is kept as you wrote it.

## Known limits

**Not tried for real yet:**

- **Installing and updating a harness** ran only against stand-ins of the makers' listings, on Linux. No real harness was downloaded or run, and nothing ran on Windows or macOS. On macOS, that a harness the server downloaded runs without Gatekeeper's prompt is assumed.
- **The engine taking the new copy** (it rebuilds the provider on the new executable) was read in its source, not watched on a running engine.

**Limits of this version:**

- **Disk.** Claude Code's copy takes about 370 MB and Codex's about 200 MB, more once unpacked; during an update both versions are there until the switch.
- **No copy for some systems:** 32-bit ARM and Intel Macs. There, install the harness yourself from its maker's page, which the app links to, then press **Look again**.
- **The makers' signatures aren't checked**, only their SHA-256 over HTTPS.
- **Updating a harness you installed yourself** lets the engine ask npm for its latest version where npm is on the server's `PATH`, which writes npm's cache under the server user's home.

Everything listed under "Known limits" in the [0.7.1](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.7.1) notes still applies.
