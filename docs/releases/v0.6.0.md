# J3 Bots 0.6.0

**Draft.** The notes for the 0.6.0 release, kept here while it is prepared. The release workflow adds the install section and the Android certificate's digest.

A room is now a group where everyone reads. It has no host: a message that names nobody reaches every member, a mention decides who answers, and the members answer at the same time. A bot's conversation header is just the bot. It still pins T3 Code 0.1.11.

How it reads is in [Experience: several bots, one goal](https://github.com/JPSAUD501/j3-bots/blob/v0.6.0/docs/product/experience.md#several-bots-one-goal).

## Updating

This release speaks **protocol 10**. A 0.5 app and a 0.6 server, or the other way round, show each other as incompatible, with a screen that says which side is behind. Update the server and every app together. Updates are served outside the protocol, so a 0.5 app or server can still update the other side across the change.

- **The server:** from any device, in Settings → About and updates, or `j3-bots update` on its machine. Either copies the databases into a snapshot first, then runs this release's one migration, 0032: it rebuilds the rooms without their host and hop limit, and gives every room a count of its bots' messages that starts at zero. Members, messages and settings are kept.
- **The desktop app:** the AppImage and the Windows install update themselves, once the download matches the release's signature. The deb and the Mac build link to this release.
- **The web client** comes with the server.
- **The Android app** updates itself.

### What changes on updating

- **Rooms have no host.** The room form asks for a name and two to six bots, nothing else, and the room's details list its members alike. A bot that hosted a room can be deleted like any other.
- **A room's hop limit is gone.** Rooms count their bots' messages instead (below). Chains between two bots outside a room keep their hop and fan-out limits.

### Rolling back

`j3-bots update --rollback` to the 0.5 release you updated from puts back the databases from the snapshot:

- the rooms and messages made since the update are lost, with the rest of the database;
- rooms get their hosts and hop limits back, as they were;
- your apps stay on 0.6.0 and show the server as behind: reinstall the 0.5.0 apps to keep using it.

Don't start 0.5.0 by hand on the updated data: it refuses a database that has migration 0032, and says to roll back.

## What's new

- **Everyone in a room reads** ([#265](https://github.com/JPSAUD501/j3-bots/pull/265), [#263](https://github.com/JPSAUD501/j3-bots/pull/263)). A message, yours or a bot's, that names nobody wakes every other member; each answers if it has something to add and otherwise stays quiet. A message that names members wakes only them, and the others read it the next time they wake. **@everyone** asks every member to answer. What reaches a member while it is busy arrives as one message when it is free.
- **The members answer at the same time** ([#264](https://github.com/JPSAUD501/j3-bots/pull/264)). Your message starts every member it wakes at once, as far as the server's turn slots allow, instead of one after another. A member still runs one turn of the room at a time, and your next message steers the turn it is running there.
- **Who is answering** ([#263](https://github.com/JPSAUD501/j3-bots/pull/263)). A quiet line at the end of a room, with their faces: "Hal is answering…", "Hal, Bo and 2 more are answering…". Nothing under the composer says whom a message goes to any more.
- **A room that talks to itself winds down** ([#265](https://github.com/JPSAUD501/j3-bots/pull/265)). The room counts its bots' messages since you last wrote there. After 6, every member is told the conversation is closing and to speak only if it is essential. After 12, a bot's message is still shown but wakes nobody, and the room shows one line saying the bots stopped answering each other and wait for you. Your next message starts the count again. A kickoff from a bot that built a team counts as your word, since only you can ask for a team.
- **A clean conversation header** ([#262](https://github.com/JPSAUD501/j3-bots/pull/262)). A bot's header shows its face and name, nothing about what it is doing: the conversation shows that, in the turn under way and its cards. A screen reader still hears each change. While the bot waits for you and its request is out of view, a **Waiting for you** pill at the end of the conversation brings it into view. A room's header keeps its members' names.

## Known limits

**Not tried for real yet:**

- **Real models in a room.** How often members answer each other, repeat each other, or reach the room's closing count was tested with scripted bots, not measured with Claude Code or Codex.
- **Android** was checked by its tests and type checks, not on a device or an emulator.
- **The desktop app** was not run for the new screens; it draws the web client.

**Limits of this version:**

- **Replies can overlap.** Members that answer at the same moment don't see each other's reply first, so two may say the same thing. They read what is already said before they speak.
- **The closing stage doesn't show.** Only the bots are told the conversation is closing; you see the line only once they stopped.
- **Answering a card or retrying** in a room doesn't restart the count; only a message you write does.
- **A blocked bot's "Limit resets at…"** no longer shows in its conversation; it is on its row in the roster and in Settings → Usage.
- **A Stop can lose a race with `create_bot`** ([#257](https://github.com/JPSAUD501/j3-bots/issues/257)), and **stopping a room doesn't reach another room** ([#258](https://github.com/JPSAUD501/j3-bots/issues/258)), as in 0.5.0.
- **For contributors:** on GitHub's Windows runner, several unrelated server tests sometimes time out together, and the next run passes ([#248](https://github.com/JPSAUD501/j3-bots/issues/248)).

Everything listed under "Known limits" in the [0.5.0](https://github.com/JPSAUD501/j3-bots/releases/tag/v0.5.0) notes still applies, apart from what this release changed about rooms.
