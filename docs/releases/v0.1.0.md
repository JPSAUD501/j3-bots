# J3 Bots 0.1.0

The first release of J3 Bots.

J3 Bots gives you a small team of persistent AI teammates ("bots") that run on your own machine, on the Claude Code and Codex subscriptions you already have. Each bot has a name, a job, one ongoing conversation with you and its own memory. Bots keep working when you close the app: they run routines on a schedule or when a webhook calls, message each other, and work together in rooms. J3 Bots drives an unmodified [T3 Code](https://github.com/pingdotgg/t3code) server as its engine, and installs and runs it for you. This release pins T3 Code 0.1.11, its newest stable release on 2026-11-22.

## What is in this release

- **The server**, for Linux on x64 and arm64 with systemd: `j3-bots-0.1.0-linux-x64.tar.gz`, `j3-bots-0.1.0-linux-arm64.tar.gz`, `install.sh` and `SHA256SUMS`. Each archive carries the Node it runs on. It runs bots on Claude Code and Codex, with conversations, memory, approvals, questions, credential requests, attachments, routines, messages between bots, and rooms with a host, mentions and budgets. It runs as a systemd user service. `j3-bots doctor` says what an install is missing, and `j3-bots update` moves to a newer release, keeping a snapshot to roll back to.
- **The web client**, served by the server. Served over HTTPS, it installs as an app and shows notifications.
- **The desktop app**, for Linux (AppImage and deb), macOS (dmg and zip, x64 and arm64) and Windows (installer). It has a tray, a global shortcut, the system's notifications and `j3bots://` links. The AppImage and the Windows install update themselves. The deb and the Mac build say when a newer version is out and link to it.
- **The Android app**, `j3-bots-0.1.0-android-arm64.apk`, for arm64 phones. It pairs by scanning a QR code, and has the roster, conversations, cards, rooms, dictation, and sending to a bot from the share sheet. It is signed with the project's key. To check its certificate before the first install, see [Installing the Android app](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/architecture/clients.md#installing-the-android-app).

[Releasing](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/releasing.md#what-a-release-contains) lists every file of the release.

## Install

The server, on a Linux machine with systemd, as the user J3 Bots will run as, never root:

```sh
curl -fsSL https://github.com/JPSAUD501/j3-bots/releases/latest/download/install.sh | sh
j3-bots provider connect
j3-bots pair
```

`provider connect` points the bots at an endpoint in front of your subscriptions. `pair` prints the addresses the server answers on, a code and a QR code: open an address in a browser and enter the code, or scan the QR code with the Android app. A bot can do anything the user it runs as can, so on a machine with SSH keys or data you care about, run J3 Bots as a dedicated user. [Installing J3 Bots](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/install.md) explains each step.

The desktop app: download the package for your system and open it. The packages are unsigned, so macOS and Windows warn before the first open.

The Android app: download the APK on the phone, open it, and allow the browser or the files app to install apps. A later release installs over it the same way and keeps its pairing; the app does not update itself.

## Known not to work yet

- **Push notifications on Android.** The code is in the app, but this build has no Expo project and no Firebase configuration, by the project owner's choice, so the app cannot turn them on, and push has not been tried on a phone. The web client and the desktop app show notifications while they are connected.
- **No iOS app, and nothing in an app store.** Both are out of scope for now.
- **The server runs only on Linux.** It does not run on macOS or Windows. Without a systemd user manager, as in most containers, `install.sh --no-service` installs the command only, and whether bots run that way has not been checked.
- **Not run yet:** the desktop app on macOS and Windows (it has run on Linux only), a release archive on a Raspberry Pi (the server has run there from a checkout), and `j3-bots provider login`, which signs a harness in with its own account instead of an endpoint.
- **The engine can write into the running user's own `~/.claude`, `~/.claude.json` and `~/.codex`** ([#86](https://github.com/JPSAUD501/j3-bots/issues/86)), and Codex bots are offered that user's own `~/.agents/skills` ([#48](https://github.com/JPSAUD501/j3-bots/issues/48)). A dedicated user keeps your own setup out of their reach.
- **The desktop app's global shortcut on GNOME 50 under Wayland** is expected not to work: GNOME lets only an app with a reverse-DNS desktop id register one, and the app's id is not settled yet.
- **Providers are set up only from the command line** (`j3-bots provider connect`, `j3-bots doctor`). No client has a provider screen yet.

Other known problems are in the [issue tracker](https://github.com/JPSAUD501/j3-bots/issues).
