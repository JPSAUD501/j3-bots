# J3 Bots 0.1.0

The first release of J3 Bots.

J3 Bots gives you a small team of persistent AI teammates ("bots") that run on your own machine, on the Claude Code and Codex subscriptions you already have, reached through an endpoint you run in front of them. Each bot has a name, a job, one ongoing conversation with you and its own memory. Bots keep working when you close the app: they run routines on a schedule or when a webhook calls, message each other, and work together in rooms. J3 Bots drives an unmodified [T3 Code](https://github.com/pingdotgg/t3code) server as its engine, and installs and runs it for you. This release pins T3 Code 0.1.11, the newest stable release of T3 Code.

## What is in this release

- **The server**, for Linux on x64 and arm64 with systemd: `j3-bots-0.1.0-linux-x64.tar.gz`, `j3-bots-0.1.0-linux-arm64.tar.gz`, `install.sh` and `SHA256SUMS`. Each archive carries the Node it runs on. It runs bots on Claude Code and Codex, with conversations, memory, approvals, questions, credential requests, attachments, routines, messages between bots, and rooms with a host, mentions and budgets. It runs as a systemd user service. `j3-bots doctor` says what an install is missing, and `j3-bots update` moves to a newer release, keeping a snapshot to roll back to.
- **The web client**, served by the server.
- **The desktop app**, for Linux (AppImage and deb), macOS (dmg and zip, x64 and arm64) and Windows (installer). It has a tray, a global shortcut, the system's notifications and `j3bots://` links. The AppImage and the Windows install update themselves. The deb and the Mac build say when a newer version is out and link to it.
- **The Android app**, `j3-bots-0.1.0-android-arm64.apk`, for arm64 phones. It pairs by scanning a QR code, and has the roster, conversations, cards, rooms, dictation, and sending to a bot from the share sheet. It is signed with the project's key. To check its certificate before the first install, see [Installing the Android app](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/architecture/clients.md#installing-the-android-app).

[Releasing](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/releasing.md#what-a-release-contains) lists every file of the release.

## Before you install

The server needs a Linux machine with systemd, on x64 or arm64, and:

1. **The user it runs as.** A bot can do anything that user can, so on a machine with SSH keys or data you care about, create a dedicated user ([Choose the user it runs as](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/install.md#choose-the-user-it-runs-as)). Then turn lingering on for it, so the server keeps running when you log out of an SSH session and starts at boot: `sudo loginctl enable-linger <user>`. Do every step below as that user.
2. **Claude Code, Codex or both, installed as that user**, before you run `install.sh`: [Claude Code](https://code.claude.com/docs/en/setup), [Codex](https://developers.openai.com/codex/cli). If you install one later, run `j3-bots service install` again, so the service finds it.
3. **An endpoint you run in front of your subscriptions**, one that speaks Anthropic's Messages API and OpenAI's Responses API, such as [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI). It is the tested way for bots to reach their models. Signing each harness in with its own account (`j3-bots provider login`) has been started but never completed with a real account.
4. **About 1.5 GB of free memory** while a bot works, and about 3 GB of free disk.

## Install

The server, as the user from step 1, never root:

```sh
curl -fsSL https://github.com/JPSAUD501/j3-bots/releases/latest/download/install.sh | sh
```

`~/.local/bin` is not on your `PATH` until your next login: open a new login shell, or run the command as `~/.local/bin/j3-bots`. Then:

```sh
j3-bots provider connect
j3-bots pair
```

`provider connect` asks for your endpoint's base URL, without `/v1`, and its key. `pair` prints the addresses the server answers on, a code and a QR code: open an address in a browser and enter the code, or scan the QR code with the Android app. Once a provider is ready, the web client asks for your first bot's name, and the bot speaks first. [Installing J3 Bots](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/install.md) explains each step.

The server answers plain HTTP on your private network by default. A browser gives a plain-HTTP page other than `localhost` no notifications and does not install it as an app: for those, serve it over HTTPS ([Reaching J3 Bots from elsewhere](https://github.com/JPSAUD501/j3-bots/blob/v0.1.0/docs/operations/exposing.md)).

The desktop app is unsigned, so macOS and Windows warn before the first open:

- **Linux:** make the AppImage executable (`chmod +x J3-Bots-x86_64.AppImage`) and run it, or install the deb with `sudo apt install ./j3-bots_0.1.0_amd64.deb`.
- **macOS:** download the dmg for your Mac, arm64 for Apple silicon or x64 for Intel; the zip is for updates. macOS blocks the first open: in System Settings → Privacy & Security, choose Open Anyway.
- **Windows:** run the installer. When SmartScreen warns, choose More info, then Run anyway.

The Android app: download the APK on the phone, open it, and allow the browser or the files app to install apps. A later release installs over it the same way and keeps its pairing; the app does not update itself.

## Known not to work yet

- **This APK cannot receive push notifications.** The web client and the desktop app show notifications while they are connected.
- **No iOS app, and nothing in an app store.** Both are out of scope for now.
- **The server runs only on Linux.** It does not run on macOS or Windows. Without a systemd user manager, as in most containers, `install.sh --no-service` installs the command only, and whether bots run that way has not been checked.
- **Not run yet:** the desktop app on macOS and Windows (it has run on Linux only), and a release archive on a Raspberry Pi (the server has run there from a checkout).
- **The engine can write into the running user's own `~/.claude`, `~/.claude.json` and `~/.codex`** ([#86](https://github.com/JPSAUD501/j3-bots/issues/86)), and Codex bots are offered that user's own `~/.agents/skills` ([#48](https://github.com/JPSAUD501/j3-bots/issues/48)). A dedicated user keeps your own setup out of their reach.
- **The desktop app's global shortcut on GNOME 50 under Wayland** is expected not to work: GNOME lets only an app with a reverse-DNS desktop id register one, and the app's id is not settled yet.
- **Providers are set up only from the command line** (`j3-bots provider connect`, `j3-bots doctor`). No client has a provider screen yet.

Other known problems are in the [issue tracker](https://github.com/JPSAUD501/j3-bots/issues).
